# HA remote update administration

Requires the Windows updater from PR #4. The legacy HA Configure form previously accepted a trusted HTTPS catalog URL containing exactly {"version":"0.2.0"}. The server operator must publish only the version whose signed Windows agent ZIP/manifest/signature are already available on the separately provisioned PC mirror. No redirects or credentials in catalog URL. Blank disables update controls. HA polls every 5 minutes and validates again on install. Native update entity uses advertised agent_version and remote_update capability, sends a short-lived UUID request on command/update (non-retained), and correlates status by request ID. Success only completes after the agent reports the requested installed version; failures and rollback remain visible in attributes. No auto-updates, no new gaming action. HA persists the pending request before publishing and restores correlation after a restart/reload within its 20-minute tracking window, without resending the command. A timeout is unconfirmed rather than proof of failure. Approved catalog publishing, signing environment setup, HTTPS mirror, end-to-end tests and permissions are follow-up deployment gates. Do not expose arbitrary update URLs through MQTT.

**Since HA 0.5.6:** the legacy Windows update settings page was removed from Configure. Existing saved `update_catalog_url` values remain unchanged and remain subject to the same validation when used; there is no UI to provision a new catalog URL in this version. The update entity and any explicitly authorized manual update path remain separate from Configure; the menu cleanup does not trigger or authorize an update.
